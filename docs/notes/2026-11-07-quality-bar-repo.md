## 1. Locking and supply chain

### 1.1 server-scan: three lock artifacts, one source of truth

| File | Generated by | Consumed by | Checked in CI? |
|---|---|---|---|
| `uv.lock` (645 sha256 entries) | `uv lock` | dev, CI, and every `uv sync --all-groups --locked` (`SS/.github/workflows/ci.yml:57,226,316`) | **Yes.** `--locked` fails if `pyproject.toml` and the lock disagree |
| `requirements.txt` (419 hashes) | `uv export --format requirements-txt --no-dev --no-emit-project -o requirements.txt` (header line 2) | the **Containerfile**: `pip install --no-cache-dir --no-compile -r requirements.txt` (`SS/Containerfile:17-19`), and the air-gap mirror: `pip download -r requirements.txt -d ./wheelhouse --no-deps` (`SS/docs/air-gap.md:41`) | **No** |
| `pylock.toml` (PEP 751, 419 hashes) | `uv export --format pylock.toml --no-dev --no-emit-project -o pylock.toml` | **nothing in the repo.** It is documented only as a mirroring input. Each entry carries its URL, size, upload time and index | **No** |

- **Why all three.**
  - `uv.lock` is the only lock humans edit, through `uv lock`.
  - The two exports exist for the air-gapped build: "Nothing in the production build or runtime path may reach the public internet" (`SS/docs/air-gap.md:3`).
  - `requirements.txt` is what pip-based tooling and the image actually consume. `pylock.toml` is the standards-format equivalent, offered to mirror tooling.
  - I found no recorded reason for keeping *both* exports, and nothing reads `pylock.toml`.
- **Hashes are enforced implicitly.** Every line in `requirements.txt` carries `--hash=sha256:…`, so pip enters hash-checking mode on its own. The Containerfile does not pass `--require-hashes` or `--no-deps` explicitly.
- **No CI drift check exists for the exports.**
  - `SS/docs/air-gap.md:86-92` ("What's still open") lists "a CI job that fails the build if `requirements.txt`/`pylock.toml` drift from `pyproject.toml`" as still open.
  - The audit `SS/docs/notes/2026-09-audit-deploy-ci-docs.md:234` (finding C5) proposes "re-run both `uv export` commands into a temp dir and `diff`". It was never added.
  - Regeneration is a manual obligation in CLAUDE.md (`SS/CLAUDE.md:95-97`, `:397`).
- **Exact-pinning policy.**
  - Every direct runtime and dev dependency is `==`, with a reason comment on any pin that isn't obvious (`SS/pyproject.toml:9-103`).
  - Some pins hold a version *below* the newest because that is what the air-gapped mirror carries: `redis==8.0.1` ("the newest version this platform's actual air-gapped mirror carries"), `ucsmsdk==0.9.18` and `ucscsdk==0.9.0.8`. The pinned-down APIs were diffed programmatically before the downgrade.
  - Transitive dependencies that the code imports directly are promoted to direct pins (`starlette==1.6.0`, caught by `deptry` DEP003).
  - Unused vulnerable dependencies are deleted rather than bumped (`python-multipart`, ADR-0013).
- **Index config for the air gap** (`SS/pyproject.toml:105-119`).
  - The mirror URL is not committed. It comes from `UV_INDEX_URL`/`UV_DEFAULT_INDEX` or a local `uv.toml`.
  - `index-strategy = "unsafe-best-match"` is set because every configured index is the operator's own mirror.
- **CI audit steps.**
  - `uv run --with pip-audit pip-audit --skip-editable` and `uv run --with deptry==0.24.0 deptry . --known-first-party app` (`ci.yml:104-113`). Both are ephemeral `--with` installs, so neither tool enters the image or the dev group.
  - `npm audit` (blocking) in the frontend job (`ci.yml:265`).
- **No dependency bot.** Renovate was never used. Dependabot was added and then removed, as ADR-0013 records:
  - Its `uv` ecosystem edited `requirements.txt`, "a *generated export* … as though it were the place dependencies are declared", which left it "asserting versions `uv.lock` does not contain".
  - It also bumped `pydantic-core`, which `pydantic` pins exactly.
  - The replacement is a quarterly manual checklist (`SS/CLAUDE.md:449-470`) covering pins, `pip-audit`/`npm audit`, runtime deprecations, the base image and the `ty` version.
- **npm.**
  - `frontend/package.json` uses caret ranges (`"react": "^19.2.8"`). The committed `package-lock.json` (lockfileVersion 3) is the pin.
  - CI and the Containerfile both run `npm ci` (`SS/frontend/Containerfile:3-4`).
  - The air gap is handled by `npm ci --offline` against Verdaccio or a tarball cache (`SS/docs/air-gap.md:55-65`).
  - There is no `.npmrc`.
- **Container base images are pinned to a minor tag, never a digest.**
  - `ubi9/ubi-minimal:9.8`, `ubi9/nodejs-22:9.8`, `ubi9/nginx-124:9.8`.
  - CPython comes from a python-build-standalone tarball, `ADD https://github.com/…/${PYTHON_BUILD_STANDALONE_RELEASE}/…` with pinned ARGs but **no `--checksum`** (`SS/Containerfile:1-4`). `air-gap.md` says how to replace that URL with an internal artifact store.
- **Image inventory for mirroring.**
  - `SS/deploy/air-gapped-images.txt` is "generated by hand… Re-check this file whenever one of those changes".
  - **It has drifted.** It lists `ubi9/nodejs-22:latest` and `ubi9/nginx-124:latest`, while the Containerfile uses `:9.8`. Nothing tests it.
- **Helm subcharts are vendored for the air gap.**
  - `Chart.lock` is committed with a digest, and `charts/mongodb-19.1.16.tgz` and `charts/redis-28.0.15.tgz` are in git.
  - The reason is in `Chart.yaml`: "Air-gapped: run `helm dependency update` on a connected machine and commit the resulting charts/*.tgz".
- **CI action pinning:**
  - every action is pinned to a 40-character SHA with a `# vX.Y.Z` comment (ADR-0013, the tj-actions incident);
  - uv is pinned to `version: "0.12.5"`;
  - helm deliberately uses the runner's preinstalled binary and prints `helm version`, because a linter isn't worth a SHA-pinned action (`ci.yml:122-130`).
- **`.gitattributes`** has a single line: `frontend/public/architecture/*.html linguist-generated=true`. Nothing in it covers lockfiles: no linguist or merge settings.

### 1.2 herzi

- **Go modules.**
  - `go.mod` has exact module versions (`go 1.27.3`, no `toolchain` line), and `go.sum` is committed.
  - CI's composite action uses `actions/setup-go` with `go-version-file: go.mod` (`HZ/.github/actions/go/action.yml`), so the toolchain follows `go.mod`.
  - Caches are keyed on `hashFiles('go.sum')`, plus an ISO week for build caches. Only `main` saves them; other refs restore only.
- **Tool pinning** (`HZ/Makefile`):
  - `CONTROLLER_TOOLS_VERSION ?= v0.22.0`, `ENVTEST_VERSION ?= v0.25.0`, `ENVTEST_K8S_VERSION ?= 1.37.0`, `GOLANGCI_LINT_VERSION ?= v2.15.0`, `GOVULNCHECK_VERSION ?= v1.9.0`, each installed into `./bin` with `GOBIN=$(LOCALBIN) go install …@$(VERSION)`.
  - CI caches each binary under a key that includes the version.
- **Downloaded binaries are verified against upstream checksums** (`HZ/.github/workflows/ci.yml:98-120`):
  ```bash
  curl -sSfL -o "$RUNNER_TEMP/helm.tar.gz" https://get.helm.sh/helm-v4.3.1-linux-amd64.tar.gz
  # Source: https://get.helm.sh/helm-v4.3.1-linux-amd64.tar.gz.sha256sum
  echo "0403a88a…fe54b  $RUNNER_TEMP/helm.tar.gz" | sha256sum --check --strict
  ```
  - promtool is handled the same way (`PROMETHEUS_VERSION: 3.15.1` plus `PROMETHEUS_SHA256`).
  - The chart-test dependency is pinned: `pip install PyYAML==6.0.3`.
  - Checkout uses `persist-credentials: false`.
- **Dockerfile.**
  - `FROM golang:1.27.3 AS builder`: an exact tag, no digest. `go mod download` runs before the source `COPY`, for the layer cache.
  - The runtime is `gcr.io/distroless/static:nonroot`, **a floating tag**, with `USER 65532:65532`.
  - OCI labels carry `VERSION` and `COMMIT`. The build is `-trimpath -ldflags "-s -w -X main.version=… -X main.commit=…"`.
  - A `prebuilt` target lets CI build the binary once and copy it into the image.
- **`.dockerignore` is an allowlist**: `**`, then `!go.mod`, `!go.sum`, `!cmd/**`, `!internal/**`, `!bin/manager`, and test files are excluded again.
- **Air gap.** `HZ/docs/ops/operating.md:75` says "Air-gapped clusters must mirror both Dockerfile base images".
- **Gaps:**
  - CI has no `go mod tidy` diff check and no `go mod verify` (grep finds neither);
  - no digest pins;
  - no Renovate or Dependabot.

### 1.3 Takeaways

1. **One lock is the source of truth.** Every other lock artifact is a generated export, and CI diffs it against a fresh export. Neither exemplar runs that diff, though server-scan's own audit asked for it.
2. **The image installs from the export, with hashes required.**
3. **Pin to what the mirror carries**, and write the reason beside the pin.
4. **No dependency bot.** Use a manual quarterly pass with blocking `pip-audit` and `npm audit` instead.
5. **Pin downloads by checksum**, as herzi does. Base-image digests would be the next step; neither repo has taken it.
6. **Vendor anything that would otherwise be fetched at deploy time**, such as subchart tgz files and the Swagger bundle (SS ADR-0040).

## 3. Observability: the exporter

### 3.1 server-scan, `SS/backend/app/observability/metrics.py` (234 lines) and `fleet_gauges.py` (369 lines)

- **Registry.** It uses the default `prometheus_client` registry: "that's the library's own documented pattern" (module docstring).
- **Naming.**
  - The RED and dependency metrics are unprefixed: `http_requests_total{method,path,status}`, `http_request_duration_seconds{method,path}`, `dependency_call_duration_seconds{dependency,outcome}` with explicit buckets `(0.01 … 20)`, `cache_operations_total{operation,outcome}`, `mongo_ping_failures_total`, `auth_logins_total{outcome}`.
  - The business gauges are prefixed `server_scan_*`.
  - Timestamps use the `_timestamp_seconds` suffix, "so `time() - metric` is age and stays correct however late the scrape is" (ADR-0029).
- **Label bounds.**
  - `path` is the route template, with `"<unmatched>"` for 404s: "a sentinel bounds label cardinality" (`SS/backend/app/main.py:235-237`).
  - `LOGIN_OUTCOMES` is a fixed tuple, **pre-created at 0** because "a labelled counter has no series until its first increment, so a rare outcome would be absent from dashboards and `rate()` would miss its first event" (`metrics.py:43-60`).
  - The dependency `outcome` is a classified reason such as `ok`, `invalid_credentials`, `connect_timeout`, `read_timeout`, `http_503` or `cancelled`. It is recorded in a `finally` block, so every path is counted, cancellation included (`SS/backend/app/infrastructure/ad/client.py:120-138`).
  - **There is one unbounded label**: `server_scan_audit_events_by_actor{actor_type,actor}` carries AD login names. `deploy/README.md:465-469` accepts that "anyone who can open the Grafana datasource can see which users did how many audited actions".
- **What is measured.**
  - RED for the API.
  - Dependency latency and outcome for LDAP, the AD API and vendor rechecks.
  - Cache hit, miss and error counts.
  - **Business state as gauges computed on scrape from the source of truth** (ADR-0029, `SS/docs/adr/0029-fleet-gauges-from-mongodb.md`). The questions are "is the collector alive, how many servers are stale, unreachable or partial, the last run's outcome per collector, membership-job runs, duplicates, the policies firing, audit size and age". In detail:
    - One `$facet` aggregation, throttled by `INVENTORY_METRICS_FLEET_REFRESH_SECONDS=30`.
    - If the query fails, the gauges **keep their previous values** and `server_scan_fleet_snapshot_failures_total` increments.
    - Label sets that disappear are dropped (`test_apply_snapshot_drops_label_sets_that_vanished`).
  - Rejected alternatives (all from ADR-0029):
    - *Per-server gauges*: "10,000–50,000 time series per scrape… the per-server answer belongs in the API and UI".
    - *Pushgateway or heartbeats*: "can report a run that happened; neither can report one that did not".
    - *A background refresh task*: "adds lifecycle for no gain".
- **Exposure and protection.**
  - `@app.get("/metrics", include_in_schema=False)` is on the API port, gated by `INVENTORY_METRICS_ENABLED`. It is **unauthenticated**: "`/health`, `/auth/*` and `/metrics` stay open" (`main.py:214-252`).
  - The frontend nginx **proxies `/metrics` to browsers on purpose** (`frontend-api-proxy-configmap.yaml:81-89`: "these are all for a human with a browser").
  - The ServiceMonitor scrapes the Service directly, "never through the Route" (`backend-servicemonitor.yaml`).
- **Tests.**
  - `tests/unit/observability/test_fleet_gauges.py` (513 lines, `REGISTRY.get_sample_value`):
    - every gauge set from a snapshot;
    - vanished labels dropped;
    - a never-seen collector has no timestamp sample;
    - one query per interval;
    - old values kept on failure;
    - a failure is counted.
  - `tests/api/test_metrics_audit_wiring.py` is an integration test that runs `create_app()` with its lifespan, writes an audit event to the real Mongo, `GET /metrics`, and parses the text exposition (`_sample(body, name)`). It proves the refresher is *wired*, not just correct.
  - **No test covers the RED middleware, label bounds, the dashboard or the rules.**
- **`SS/backend/app/domain/services/health/metrics.py` is *not* Prometheus.** It is the typed registry of server facts that health *policies* can reference:
  - entries are `MetricDef(name, type: MetricType StrEnum, resolver…)`;
  - `register()` raises on a duplicate name, "so a naming collision… is a loud startup failure";
  - it is built once and passed explicitly, so tests can build a smaller one.
  
  Wingman can borrow the idea for its label vocabularies.

### 3.2 herzi, `HZ/internal/metrics/metrics.go` (308 lines)

- **Registry.** It is **injected** (`New(reg prometheus.Registerer)`). Re-registration reuses the existing collector, and a type conflict is kept as `RegistrationError()`, which `controller.New` rejects (`docs/design/notes/metrics.md`).
- **Naming.** Everything is `herzi_*`:
  - `_total` counters;
  - `_seconds` histograms with explicit buckets for the install POST (`.05 … 30`);
  - `herzi_last_successful_reconcile_timestamp_seconds`;
  - 0/1 gauges for states (`herzi_pool_blocked`, `herzi_pool_probe_mode`, `herzi_config_valid`).
- **Bounded vocabularies, enforced in code:**
  - `installKinds` is an 18-entry allowlist. Anything else becomes `other`: "kind is bounded to the known set so labels cannot grow" (`:211-235`).
  - An HTTP code outside 100–599 becomes `none`.
  - `BlockReasons()` maps free text to about 15 fixed reason kinds, "excluding object names, timestamps and external errors" (`:262-305`).
  - `failure_class` is **one-hot over `{capacity, other, unknown}`**: every class is always present, either 0 or 1.
- **Series lifecycle.**
  - `ObservePool` calls `DeletePartialMatch` on stale reasons first, "so a recovered pool does not retain an earlier diagnosis".
  - `ForgetPool` deletes every series for a pool that has gone away.
- **Configuration is exported as a metric** so alert rules stay literal: `herzi_stuck_after_seconds` is the configured threshold, and the alert is `herzi_oldest_open_run_seconds > ignoring(pool) group_left herzi_stuck_after_seconds`.
- **Exposure and protection** (`cmd/main.go:323-347`, `charts/herzi/templates/metrics-auth.yaml`):
  - controller-runtime's metrics server serves **HTTPS on :8443** with `FilterProvider = filters.WithAuthenticationAndAuthorization`, which calls TokenReview and SubjectAccessReview;
  - the chart grants the pod `create` on `tokenreviews` and `subjectaccessreviews`, and a `<release>-metrics-reader` ClusterRole `nonResourceURLs: [/metrics] verbs: [get]`;
  - that role is bound only to `rbac.metricsReader.subjects`;
  - the ServiceMonitor endpoint is `mergeOverwrite`d from raw values, so the bearer token secret and TLS config pass through (`hack/chart/monitoring-values.yaml`).
- **Tests** (`metrics_test.go`, `round2_test.go`), each using its own `prometheus.NewRegistry()`:

  | Test | What it pins |
  |---|---|
  | `TestCatalogueAndForget` | The **exact set** of metric families, their types and their label names. `require.Len(families, len(expected))` makes adding a metric without updating the test a failure. Also checks that `ForgetPool` leaves no `pool` label |
  | `TestBoundedReasons`, `TestReasonVocabulary` | Free text maps to the fixed vocabulary, with `other` as the fallback |
  | `TestInstallErrorKindsAreBounded` | "an unknown kind must not become its own label value"; a bad HTTP code becomes `none` |
  | `TestRemovedMetricsAreNotRegistered` | Retired names stay retired |

### 4.2 Rule design

- **server-scan** (11 groups, 62 rules):
  - **Recording rules collapse the per-replica copies of fleet gauges**: `server_scan:<gauge>:max = max by (namespace, <labels>) (<gauge>)`. Every API replica exports the same fleet-wide gauges, and "an alert on the raw series would fire once per replica". The rejected alternatives were a leader-elected exporter and dropping pod labels.
  - Derived ages: `server_scan:collector_silent_seconds = time() - max by (...) (…_timestamp_seconds)`.
  - Dependency failure ratio: `sum by (dependency)(rate(…_count{outcome!~"ok|invalid_credentials|verified|not_found|cancelled"}[10m])) / sum by (dependency)(rate(…_count{outcome!="cancelled"}[10m]))`.
  - Alerts are all `severity: warning`, with `summary` and `description`, and the description contains the first command to run (`oc get jobs -n <ns>`). There is no `runbook_url`.
  - "A missing series makes an alert inert, never firing (no `or vector(0)`); the one deliberate `absent_over_time` is leaf mode's ServerScanApiDown".
- **herzi** (10 alerts):
  - `absent(herzi_config_valid)` for 10m is critical (controller down);
  - `time() - herzi_last_successful_reconcile_timestamp_seconds > 600` is critical;
  - `herzi_pollers == 0` is critical;
  - the rest are warnings;
  - **every alert has a `runbook_url`** pointing at `docs/ops/runbook.md#<anchor>`. Each runbook section gives the meaning, the **exact PromQL to confirm**, the remediation and what *not* to do ("Do not raise the open-run cap to cure missing hardware").

## 6. Release and versioning (both repos are nearly identical)

1. **The version is computed, not written down.** `PaulHatch/semantic-version@<sha> # v6.0.2` with `tag_prefix: "v"` reads Conventional Commits since the last `v*` tag: `!`/`BREAKING CHANGE` is a major bump, `feat` a minor, anything else a patch (SS ADR-0010).
2. **A forward-only guard** (`SS/ci.yml:480-498`, `HZ/ci.yml:184-202`) fails if the tag is empty, already exists on another commit ("refusing to re-tag"), or doesn't sort after the previous tag. A re-run on the same commit is idempotent.
3. **Tag**: an annotated `git tag -a vX.Y.Z` pushed by the bot.
4. **Release notes from commit subjects.** Inline Python groups Breaking, New features, Fixed, Performance and Documentation. `refactor/test/chore/ci` are dropped as "nothing an operator can observe". `gh release create` is retried 3 times. **There is no CHANGELOG**: a hand-maintained one "sat under `## Unreleased` for six releases".
5. **Image tags.**
   - server-scan uses `docker/metadata-action`: `{{version}}` (no `v`), `{{major}}.{{minor}}`, `{{major}}`, `latest`, `sha-<sha>`.
   - herzi uses a bash array: `X.Y.Z`, `X.Y`, `sha-<7>`, `latest`, plus `X` only when the major isn't 0.
   - Both charts tell users never to deploy `latest`.
6. **Build once.**
   - herzi builds the binary once in the `image` job and hands it to `publish` as an artifact.
   - server-scan's `prebuild` fills the GitHub Actions cache in parallel with the tests and pushes nothing ("untested code never reaches the registry").
   - `publish` `needs:` every job.
7. **Deploy.** server-scan's `deploy` job does the following:
   - rsyncs the templates into the GitOps repo;
   - pins `tag:` and `appVersion` with `sed` ("not yq: `yq -i` re-emits the whole file");
   - asserts exactly two tag lines changed;
   - runs `helm lint` and `helm template` the way Argo will;
   - pushes with rebase retries.
8. **Chart version.** It is manual in both repos (SS `version: 0.4.0`, HZ `0.1.0`). **The in-repo `appVersion` is stale in server-scan** (`"1.0.0"`, while tags are in the v11 range); only the GitOps copy is pinned. Don't copy that.
9. Binary and image metadata: OCI labels `org.opencontainers.image.{version,revision,source}`, and herzi's `-X main.version/commit`.

### 7.3 The exporter: what Wingman should export

**Label rules for `docs/ops/metrics.md`:**
- Every label value comes from an enum, and anything unknown becomes `other`. Never use user names, cluster names, MR IIDs, project or file paths, raw exception text, or HTTP codes outside 100–599 (those become `none`).
- `route` is the FastAPI route template.
- There is no `team` label by default, because the number of day2 teams grows. If one is ever added, document its bound and delete its series when the team disappears, as herzi's `ForgetPool` does.
- There is no per-cluster label: per-cluster answers belong in the UI and API (SS ADR-0029's rejected "per-server gauges").
- Suffixes: `_total` for counters, `_seconds` for durations, `_timestamp_seconds` for "when".
- Use the target labels (`job`, `namespace`, `pod`) from the ServiceMonitor instead of adding a `service` label. The one exception is `build_info`.
- Configured thresholds that alerts need are exported as gauges (herzi's `herzi_stuck_after_seconds`), so the rules file stays literal and testable.

### 7.4 Alerts, rules and dashboard

**Rules setup (P1):**
- Rules live in `chart/files/alerts.rules.yaml`, a plain file in the herzi style.
- The PrometheusRule template adds the label `openshift.io/prometheus-rule-evaluation-scope: leaf-prometheus` by default (SS, because Wingman runs on OpenShift).
- The test runner is `scripts/test-alerts.sh`: `promtool check rules` plus `promtool test rules chart/tests/alerts.test.yaml`, with promtool pinned and checksum-verified in CI.
- Recording rules `wingman:<gauge>:max` collapse the per-replica copies of the on-scrape gauges.

## 8. What not to copy

- **server-scan:**
  - The `/metrics` endpoint is unauthenticated **and deliberately proxied to browsers through the frontend Route**. Usernames appear as metric labels (`server_scan_audit_events_by_actor`).
  - No drift check for `requirements.txt` and `pylock.toml`. `pylock.toml` is generated but consumed by nothing.
  - `air-gapped-images.txt` has drifted (`:latest` versus `:9.8`).
  - Base images are pinned to a minor tag only. The CPython `ADD` has no `--checksum`.
  - Alert rules are templated and have no promtool unit tests in CI. The empty-threshold bug was caught only by OpenShift admission.
  - The dashboard threshold line has drifted from the chart default (43200 versus 21600). The frontend replicas panel hard-codes the release name and `/ 3`.
  - The in-repo `Chart.yaml` `appVersion` is stale.
  - Unprefixed `http_*` and `dependency_*` names (`http_requests_total`) can collide with other apps in a shared Prometheus.
  - The chart writes the cluster-wide `cluster-monitoring-config`.
  - No `.env.example` parity test.
- **herzi:**
  - The runtime base image `distroless/static:nonroot` floats.
  - No `go mod tidy` or `go mod verify` check.
  - `appVersion` is static at 0.1.0 while `image.tag` defaults to it.
  - `cmd/` tests are excluded from CI (already in quality-bar Part F).
- **Both:** the no-attribution-trailer hook and rule are the owners' preference, not a quality practice.
