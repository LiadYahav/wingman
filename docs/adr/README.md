# Architecture decision records

One file per decision, numbered, never deleted. A decision that changes is
superseded by a new ADR that says so; the old one stays and gets a
`Superseded by` status line. A decision whose feature is kept in the code but
held off (its setting off, until the team needs it) is `Parked <date>`, with
why, and a dated amendment says what to do to bring it back.
Three numbers have no file: 0046, 0049 and 0051
were reserved for planned workstreams (`docs/ideas/single-pane.md`); 0046 was
never used, and the other two wait for their work to be built. Every ADR uses the template below. The
**Verification** section names the test or measurement that pins the
decision, so the next person can tell it is still true.

```
# ADR-NNNN: <the decision, as a sentence>

Date: YYYY-MM-DD
Status: Proposed | Accepted | Parked YYYY-MM-DD | Superseded by ADR-NNNN | Superseded in part by ADR-NNNN

## Context
## Decision
## Alternatives rejected
## Consequences
## Verification
```
