# Upgrade: 3.8 → 3.9 (Quick Links; the hub, the team's links and the ArgoCD counts are optional)

> **3.13.1 removed the status dots and the ArgoCD counts** (ADR-0052's
> 2026-11-13 amendment): Wingman lists the links and never calls them.
> Going to 3.13.1 or later, skip step 3's third check and step 4, and leave
> `quickLinks.argocdTokensSecret` out of step 5; step 6 has no dots or
> counts to see. A Wingman that went through this guide before can delete,
> when convenient: `quickLinks.status`, `quickLinks.sslVerify` and
> `quickLinks.argocdTokensSecret` from its values (the chart ignores them;
> `helm upgrade ... --reset-then-reuse-values --set quickLinks.status=null
> --set quickLinks.sslVerify=null --set quickLinks.argocdTokensSecret=null`);
> the `ping:` and `argocd:` keys of the links in `quickLinks.sections` (the
> page names each one as an unknown key until then); the tokens Secret
> (`kubectl -n <ns> delete secret wingman-argocd-tokens`) and the
> `wingman-reader` account in each ArgoCD.

For an agent inside the disconnected environment. Follow the steps in order.
**STOP** means: change nothing more, finish the report (step 7) and hand it
back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is `3.9.0` or a later 3.9 release.

## 1. What changes

| Area | 3.8 | 3.9 |
|---|---|---|
| Sidebar | — | **Quick Links** (`/quick-links`), for admins only: a card for the hub Wingman runs on and for every MCE of the day1 repo, by site, each opening the cluster's ArgoCD with its console beside it; then the team's own links; a status dot on every link, and for an ArgoCD with a token its applications' sync and health counts (ADR-0052) |
| day1 | — | Checks each link on the page while someone reads it (`HEAD`, then `GET`; no credential sent), at most 8 at once, 3 s each, cached 60 s; reads an ArgoCD's application list with its read-only token |
| Chart | — | `quickLinks.*` (all optional). A new ConfigMap `wingman-quick-links` (the links file), mounted in day1; the ArgoCD tokens Secret, when named |
| Metrics | — | Dependencies `link_check` (`check_link`) and `argocd` (`list_applications`) (`docs/ops/metrics.md`) |

With nothing set, the page lists every MCE when `clusterStatus.mceDomain`
(or `quickLinks.domain`) is set, and says what to set otherwise. The steps
below add the hub, the team's links and the counts. Each is optional.

## 2. What to bring in from the connected side

The three images of `<tag>` and the repository at `v<tag>`, as for 3.8.
Nothing else: the icons ship in the web image.

## 3. Check before you set anything (read-only)

1. **The addresses.** In a browser on the inside network, open one MCE's
   ArgoCD at `https://openshift-gitops-server-openshift-gitops.apps.<mce>.<domain>`
   and its console at `https://console-openshift-console.apps.<mce>.<domain>`,
   with `<domain>` the release's `clusterStatus.mceDomain`. Both open: the
   defaults fit. Another pattern: note it for step 5 (`quickLinks.argocdUrlTemplate`,
   `quickLinks.consoleUrlTemplate`, with `{cluster}` and `{domain}`). Only
   some clusters differ (often the hub): note their addresses for
   `quickLinks.clusters`.
2. **The hub's name**, as in its routes: `oc get ingresses.config cluster -o jsonpath='{.spec.domain}'`
   on the hub answers `apps.<hub name>.<hub domain>`.
3. **day1 reaches them.** From a day1 pod:

   ```bash
   kubectl -n <ns> exec deploy/wingman-day1 -- python -c \
     "import httpx; print(httpx.head('https://openshift-gitops-server-openshift-gitops.apps.<mce>.<domain>', timeout=5).status_code)"
   ```

   Any status code: go on. A certificate error: the routes use an internal
   CA; put it in `tls.caBundle` (already mounted) or `quickLinks.sslVerify`.
   No answer: day1's egress does not reach the routes; the dots will be
   down. Record it and go on, or **STOP** if the team wants the dots. Don't
   add a network policy to fix it.

## 4. The ArgoCD tokens (optional, for the counts)

For each ArgoCD whose card should show counts, an account that may only
list applications, and its token. OpenShift GitOps writes `argocd-cm` and
`argocd-rbac-cm` from its `ArgoCD` resource, so add them there (as that
ArgoCD's admin), then make the token:

```yaml
# oc -n openshift-gitops edit argocd openshift-gitops
spec:
  extraConfig:
    accounts.wingman-reader: apiKey
  rbac:
    policy: |
      <the policy lines already there>
      p, role:wingman-reader, applications, get, */*, allow
      g, wingman-reader, role:wingman-reader
```

```bash
argocd login <the ArgoCD's host> --sso          # or as its admin
argocd account generate-token --account wingman-reader
```

Put the tokens in one Secret in `<ns>`, keyed by instance: the cluster's
name for a generated card (the hub's `quickLinks.hubName`, an MCE's folder
name), or the `argocd:` key of a link in `quickLinks.sections`. Never put a
token in values or in the report.

```bash
cat > tokens.yaml <<'YAML'
<hub name>: <token>
<mce name>: <token>
YAML
kubectl -n <ns> create secret generic wingman-argocd-tokens --from-file=tokens=tokens.yaml
rm tokens.yaml
```

## 5. Upgrade

The team's links go in a values file (no secrets in it), the shape in
`docs/notes/2026-11-12-quick-links-api.md` §3; the team's old homepage
`services.yaml` maps to it card by card (`href` is `url`, an icon is a key
such as `gitlab`, `argocd`, `openshift`, `grafana`, `confluence`, `cisco`,
`dell`; `ping` stays).

```bash
helm history <release> -n <ns> | tail -3          # note the current revision, for a rollback
helm upgrade <release> $CHART -n <ns> --reset-then-reuse-values \
  --set image.day1.tag=<tag> --set image.day2.tag=<tag> --set image.web.tag=<tag> \
  --set quickLinks.hubName=<hub name> \
  --set quickLinks.argocdTokensSecret=wingman-argocd-tokens \
  -f quick-links-values.yaml                       # leave out what you don't set
kubectl -n <ns> rollout status deploy -l app.kubernetes.io/part-of=wingman --timeout=5m
```

Later edits to the links need no new release: `helm upgrade` with the
edited values file (same command, without the tags), or
`kubectl -n <ns> edit configmap wingman-quick-links`. day1 shows them within
about a minute without a restart. A token change does need
`kubectl -n <ns> rollout restart deploy/wingman-day1`.

## 6. Verify

Sign in as an admin and open **Quick Links** in the sidebar:

- every MCE has a card under its site, and the hub one under **Hub**;
- within a few seconds each link has a dot: hover one for its reason;
- an ArgoCD with a token shows its counts, or a line saying why not
  (`ArgoCD refused the token (401)`: the token or its role, step 4);
- an amber panel at the top lists any mistake in the links file; the rest
  still shows.

A viewer does not see the entry. With a session token as in 3.3-to-3.4's
step 8, `curl -s -H "Authorization: Bearer $SESSION" "https://<route host>/api/day1/quick-links" | head -c 300`
answers the sections.

## 7. Roll back and report

`helm rollback <release> <previous revision> -n <ns>`: 3.8 ignores the new
keys, the new ConfigMap goes with the rollback, and the tokens Secret stays
(delete it with `kubectl -n <ns> delete secret wingman-argocd-tokens` if
it is not wanted). Report: the tag deployed, step 3's answers (the address
pattern, the hub's name, day1's reach), which ArgoCDs got tokens (names
only), and what step 6 showed.
