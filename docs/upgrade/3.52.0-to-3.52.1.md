# Upgrade: 3.52.0 → 3.52.1 (the Segments and Server Scan areas removed)

For an agent inside the disconnected environment. Follow the steps in order.
**STOP** means: change nothing more, finish the report (step 6) and hand it
back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is 3.52.1 or any later release.

## 1. What changes

The team keeps segments-manager and server-scan apart from Wingman
(ADR-0066). 3.52.0 shipped Wingman's own **Segments** and **Server Scan**
areas off by default; this release removes them, and the settings that
turned them on.

| Area | 3.52, areas off (the default) | This release |
|---|---|---|
| An admin's top bar | Wingman · Segments · Server Scan, the last two opening each system's own UI in a new tab | The same |
| A viewer | No switch | The same |
| A node's server, the cluster card's segments link | Open server-scan's and segments-manager's own pages | The same |
| The Nodes tab, MCE placement, Inventory Management, the EPG | Read server-scan and segments-manager | The same |
| `/segments`, `/server-scan` | "The area is off" | Not found (404), like any page Wingman does not have |
| `/api/day1/segments*`, `/api/day1/server-scan/*` | `501 FEATURE_DISABLED` | Gone (404) |
| `GET /api/day1/platforms` | `{id, name, url, area}` | `{id, name, url}`: every link is external |
| Settings | `DAY1_SEGMENTS_AREA`, `DAY1_SERVER_SCAN_AREA`, `DAY1_SERVER_SCAN_REFRESH`, `SERVER_SCAN_ADMIN_TOKEN`, `SERVER_SCAN_AUDITOR_TOKEN` | Gone: day1 no longer reads them |
| Chart | `day1.segmentsArea.enabled`, `day1.serverScanArea.enabled`, `day1.serverScanRefresh.enabled`, `serverScan.tokenSecret.adminKey` and `auditorKey` | Still accepted, marked deprecated in `values.schema.json`, and ignored: they render no variable and need no system's `url` |
| Metrics | The areas' `server_scan` and `segments_manager` operations | Retired (`docs/ops/metrics.md`); the dashboard's "Server-scan writes" panel is gone |

A deployment that had turned an area on (`day1.segmentsArea.enabled` or
`day1.serverScanArea.enabled` set to `true`) loses it: its admins open the
system's own UI from the top bar instead. Nothing else changes for anyone.

## 2. What to bring in from the connected side

The three images of `<tag>` and the repository at `v<tag>`, as for any
release. Building the web image from source no longer needs
`write-excel-file` or `fflate` in the npm mirror.

## 3. Discover (read-only)

```bash
# Prints only the removed keys' values (no secret is among them)
helm get values <release> -n <ns> -o json | python3 -c \
  "import json, sys; v = json.load(sys.stdin); d = v.get('day1') or {}; t = (v.get('serverScan') or {}).get('tokenSecret') or {}; print({k: d.get(k) for k in ('segmentsArea', 'serverScanArea', 'serverScanRefresh')}, {k: t.get(k) for k in ('adminKey', 'auditorKey')})"
```

Record what it prints. If an area was on, tell the team it is going (step
1); this guide does not stop for it, since the team decided on 2026-11-23.

## 4. Upgrade

```bash
helm upgrade <release> $CHART -n <ns> --reset-then-reuse-values \
  --set image.day1.tag=<tag> --set image.day2.tag=<tag> --set image.web.tag=<tag>
kubectl -n <ns> rollout status deploy -l app.kubernetes.io/part-of=wingman --timeout=5m
```

Values that still set the removed keys need no change: the chart accepts and
ignores them. Delete them from the values file when convenient. The
Secret's `admin-token` and `auditor-token` keys are no longer read; whether
to delete them is the team's call (server-scan may hand them to others).

## 5. Verify

1. `kubectl -n <ns> get configmap wingman-config -o yaml | grep -E '_AREA:|SERVER_SCAN_REFRESH'`
   prints nothing.
2. `kubectl -n <ns> get deploy wingman-day1 -o yaml | grep -E 'SERVER_SCAN_(ADMIN|AUDITOR)_TOKEN'`
   prints nothing.
3. Sign in as an admin: the top bar shows **Wingman**, then **Segments** and
   **Server Scan** for each configured system, each opening its own UI in a
   new tab.
4. On a cluster's Nodes tab, a server's name opens its page in server-scan in
   a new tab; the cluster page's network card still shows the EPG (with
   `segmentsManager.url`), and Inventory Management still counts each MCE's
   servers (with `serverScan.url`).
5. As a viewer, if you have one: no switch in the top bar.

## 6. Roll back and report

Roll back with `helm rollback <release> <previous revision> -n <ns>`: 3.52
reads its settings again, with the areas off unless the values turn them on.
Wingman keeps no state of its own, so nothing else is undone.

Report:
- the tag deployed;
- step 3's output;
- step 5's results.
