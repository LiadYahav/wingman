# Upgrade: 3.54 → 3.55 (herzi's used Agents; when to set the excluded label)

For an agent inside the disconnected environment. Follow the steps in order.
**STOP** means: change nothing more, finish the report (step 7) and hand it
back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is `3.55.0` or a later 3.55 release,
from any 3.54 release.

## 1. What changes

herzi, the inventory controller on each MCE hub, has a plan its owner
approved: label every Agent bound to a cluster `redbull.io/ever-installed`,
and once such an Agent is free again, take it out of the MCE through
`remove-server-from-mce`. Every NodePool must then exclude the label, so no
NodePool binds a used Agent again. herzi's released `main` (`0ef4d2a`,
v1.2.1) does none of it yet. This release makes Wingman ready for it, and
changes nothing until an Agent carries the label.

| Area | 3.54 | 3.55 |
|---|---|---|
| Placement's servers check | Every free Agent of a node type counts | A free Agent labelled `redbull.io/ever-installed` (or the setting's keys, when set) is no free server: the node type says "2 used, left out (herzi removes them)" |
| Inventory Management, a pool's counts | Every `INSTALLED_TO_INVENTORY` server is available | A used Agent is shown apart ("2 used", its servers in the tooltip), never available or in a total |
| Inventory Management, an MCE's card | Its pools | Also, once herzi has used Agents there or the setting is set: the NodePools of its cluster files that do not exclude the label, by cluster, each linked. herzi removes no used Agent while a NodePool that could take it lacks the exclusion |
| Inventory Management, a pool's row | Its counts | Also a badge for what herzi marked on its InfraEnv: ignored, paused, an order in flight, no hardware |
| The MCE read | InfraEnvs, and the Agents a create needs | Also one list per MCE of the Agents carrying the label and held by no AgentMachine (`<label>,!agentMachineRef`), every 30 s while Inventory is open. The existing `list agents` grant covers it |
| `day1.excludedAgentLabels` | Shipped empty | Still shipped empty. Its value, once step 6 allows it, is `["redbull.io/ever-installed"]` |

No value, Secret or grant is new: the upgrade itself is the generic one.

## 2. What to bring in from the connected side

The three images of `<tag>` and the repository at `v<tag>`, as for any
release. Nothing else for Wingman.

## 3. Discover (read-only)

1. **Live status.** `helm get values <release> -n <ns> -o json` shows
   `clusterStatus.enabled`. Without it, Inventory reads no used Agents and
   placement reads no Agents at all. Record it; it is not a reason to stop.
2. **Which herzi runs on each MCE**, with that MCE's kubeconfig:

   ```bash
   kubectl get deploy -A -l app.kubernetes.io/name=herzi \
     -o jsonpath='{range .items[*]}{.metadata.namespace}{"  "}{..image}{"\n"}{end}'
   # Its Agent rule: get, list, watch only on herzi's main; patch too once it labels Agents
   kubectl get clusterrole -l app.kubernetes.io/name=herzi -o json | python3 -c \
     "import json, sys; [print(r['metadata']['name'], rule['verbs']) for r in json.load(sys.stdin)['items'] for rule in r.get('rules', []) if 'agents' in rule.get('resources', [])]"
   ```

   Record the image and the verbs per MCE. `patch` on `agents` is the
   first sign of the release that labels used Agents.
3. **Which Agents carry the label now**, per MCE:

   ```bash
   kubectl get agents -A -l redbull.io/ever-installed --no-headers | wc -l
   kubectl get agents -A -l 'redbull.io/ever-installed,!agentMachineRef' --no-headers | wc -l
   ```

   The first is every Agent herzi labelled (bound or not), the second the
   free ones: what Inventory will show as used. Both are `0` until herzi
   labels.

## 4. Upgrade

The generic upgrade ([README](README.md#the-generic-upgrade-no-guide)):

```bash
helm history <release> -n <ns> | tail -3          # note the current revision, for a rollback
helm upgrade <release> $CHART -n <ns> --reset-then-reuse-values \
  --set image.day1.tag=<tag> --set image.day2.tag=<tag> --set image.web.tag=<tag>
kubectl -n <ns> rollout status deploy -l app.kubernetes.io/part-of=wingman --timeout=5m
```

## 5. Verify

1. The pods are ready with no restarts
   (`kubectl -n <ns> get pods -l app.kubernetes.io/part-of=wingman`), and
   `kubectl -n <ns> logs deploy/wingman-day1 | grep -c Traceback` prints `0`.
2. With a session token as in 3.3-to-3.4's step 8:

   ```bash
   # Per MCE: used Agents (None: not read), why not, and NodePools lacking the exclusion
   curl -s -H "Authorization: Bearer $SESSION" "https://<route host>/api/day1/inventory" | python3 -c \
     "import json, sys; b = json.load(sys.stdin); print(b['used_labels']); [print(m['mce'], m['used'], m['used_error'], len(m['unguarded'])) for m in b['mces']]"
   ```

   `used_labels` is `{'keys': ['redbull.io/ever-installed'], 'source':
   'herzi'}` while the setting is empty. With live status each MCE's `used`
   is step 3.3's second count (a number, `0` today), and `used_error` is
   `None`; an error naming `HubDenied` means the MCE's token lacks `list` on
   `agents`: apply the chart README's ClusterRole, as placement needs it
   too. Without live status `used` is `None`. The last number is how many
   NodePools of that MCE's cluster files do not exclude the label: all of
   them, until step 6.
3. Open Inventory Management: with no labelled Agent, nothing new shows but
   herzi's badges on pools it marked (a paused InfraEnv says "herzi
   paused").

## 6. When to set `day1.excludedAgentLabels` (later, and only then)

The value is **`["redbull.io/ever-installed"]`**, exactly that one key.
Set it only when **every** item below holds, checked on every MCE whose
clusters Wingman writes:

1. **herzi accepts the exclusion.** herzi's `main` (`0ef4d2a`, v1.2.1 and
   before) treats a NodePool with any `matchExpressions` as a problem of its
   InfraEnv's pool and orders no server for that InfraEnv, for any cluster.
   The release that implements its plan to retire used servers accepts the
   InfraEnv's own `matchLabels` plus exactly `{key:
   redbull.io/ever-installed, operator: DoesNotExist}`, and labels Agents
   on bind. Signs of it, from step 3: `patch` among its `agents` verbs,
   bound Agents labelled (step 3.3's first count above 0), and
   `dryRunRemove` in its ConfigMap
   (`kubectl get cm -A -l app.kubernetes.io/name=herzi -o yaml | grep -c dryRunRemove`).
   On any MCE where they are missing: **STOP**.
2. **herzi labelled first.** herzi's first pass labels every Agent bound
   then; an Agent freed before it is never known to be used. Its removal
   starts in dry run (`dryRunRemove: true`, herzi's default) and goes live
   one pool at a time; that is herzi's team's step, not this guide's.
3. **The chart renders the key**: patch 0002 of
   [patches/hostedclusters-setup/](patches/hostedclusters-setup/README.md),
   as [3.48-to-3.49.md](3.48-to-3.49.md) §9.2 step 1 checks.
4. **The template writes the input**: [3.48-to-3.49.md](3.48-to-3.49.md)
   §9.3, merged on the specs project.
5. **One key only.** herzi's plan blocks a pool again for any other
   expression: never add a second key, nor another label in place of this
   one.

Then [3.48-to-3.49.md](3.48-to-3.49.md) §9.4 sets the value and §9.5 gives
each existing cluster its own merge request. Change the NodePools of one
non-production cluster first, and let it sync, as herzi's plan asks (§10
step 2): a changed selector touches no node of an `InPlace` NodePool. Then
the others, one merge request per cluster.

**Inventory Management tracks it.** Each MCE's card lists the NodePools
that do not exclude the label yet ("3 NodePools in 2 clusters do not exclude
redbull.io/ever-installed"), each cluster linked, and the list shrinks as
the merge requests merge. herzi removes a used Agent only once every
NodePool that could take it excludes the label, so until the list is empty
for an InfraEnv, its used Agents stay, shown as used. A `Replace` NodePool
is listed with "(Replace: change it to InPlace first)": Wingman never gives
it the key (every node would be replaced), so the team changes it to
`InPlace` in a merge request of its own, or herzi keeps holding that
InfraEnv's used Agents.

## 7. Roll back and report

`helm rollback <release> <previous revision> -n <ns>` brings 3.54 back:
placement and Inventory count used Agents as free again. Wingman keeps no
state of its own, and this release writes nothing. Setting
`day1.excludedAgentLabels` back to `[]` is 3.48-to-3.49.md §9.6.

Report:
- the tag deployed and the revision rolled back to, if any;
- whether live status is on (step 3.1);
- per MCE: herzi's image and its `agents` verbs (step 3.2), and step 3.3's
  two counts;
- step 5's results, per MCE;
- whether step 6's five items hold, and so whether the value may be set
  (do not set it as part of this upgrade).
