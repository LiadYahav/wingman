# Upgrade: 3.44 → 3.45 (image mirrors in a flavor, optional)

For an agent inside the disconnected environment. Follow the steps in order.
**STOP** means: change nothing more, finish the report (step 7) and hand it
back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is `3.45.0` or a later 3.45 release.

## 1. What changes

| Area | 3.44 | 3.45 |
|---|---|---|
| A flavor | Cannot carry image mirrors | May give the cluster's own mirrors, `image_content_sources` (`[{source, mirrors}]`), and `disable_idms_merge` (`true`: only those, the MCE's default mirrors dropped), each a preset or locked (ADR-0063). The flavor editor has them under Basics, the flavor's Overview lists them, the create form shows them |
| The cluster file | — | `imageContentSources` and `disableIdmsMerge: true`, written only when given. Without them, every file is written exactly as before |
| Drift and a flavor's merge requests | — | A locked value is compared as the hostedclusters-setup chart merges the mirrors, and a flavor's per-cluster merge request writes it |
| Refused | — | `disable_idms_merge: true` with no mirrors of the cluster's own (it would have none at all); a flavor with mirrors while the specs project's `cluster-template.j2` does not read them; a create whose rendered file does not hold them as given |
| Chart, Secrets, grants, metrics | — | Nothing new |

Nothing changes until a flavor is given mirrors: the upgrade is the image
tags (step 5). The specs project's template needs the lines of step 4
**before** anyone saves a flavor with mirrors; until then such a save is
refused with a message naming this guide, and nothing else is affected.
You may add the lines in this upgrade, or later, when the first flavor
needs mirrors. The team decides; record which.

## 2. What to bring in from the connected side

The three images of `<tag>` and the repository at `v<tag>`, as for any
release. The reference template is in that repository:
`dev/gitlab-fixtures/wingman/cluster-specs/cluster-template.j2`.

## 3. Discover (read-only)

In the specs project (`gitlab.specsProjectId`), open `cluster-template.j2`
at the project root on the default branch.

1. **Does it already read the inputs?** Search it for
   `image_content_sources` and `disable_idms_merge`.
   - Both are there: the template is already done. Skip step 4's MR and
     do its checks only.
   - Neither is there: step 4 adds them.
   - Only one is there: **STOP**. Someone started this by hand; report what
     the template has.
2. **Does it write the keys itself?** Search it for `imageContentSources`
   and `disableIdmsMerge`. If either is written by the template already
   (for every cluster, from a constant or another input), **STOP** and
   report the lines: adding step 4's lines would write the key twice, and
   day1 refuses a file with a key twice.
3. **Where its top-level keys are.** Note the line `nodepool:` (the
   nodepool list) at column 0, and whether a `{% if ... %}` block for
   `platform` sits above it. Step 4's lines go directly above `nodepool:`,
   at column 0, outside every `{% for %}` and `{% if %}` block.

## 4. Add the lines to the specs project's template (optional, through an MR)

Open an MR on the specs project that adds exactly these lines to
`cluster-template.j2`, directly above `nodepool:` (step 3.3). Keep the
indentation as written: the `imageContentSources:` and `disableIdmsMerge:`
lines start at column 0, the template tags too.

```jinja
{% if image_content_sources | default([]) %}

# The cluster's own image mirrors; the chart merges them with the MCE's
# defaultImageContentSources unless disableIdmsMerge is true.
imageContentSources:
{% for entry in image_content_sources %}
  - source: {{ entry.source | tojson }}
    mirrors:
{% for mirror in entry.mirrors %}
      - {{ mirror | tojson }}
{% endfor %}
{% endfor %}
{% endif %}
{% if disable_idms_merge | default(false) %}

# Only the mirrors above: the MCE's default mirrors are dropped.
disableIdmsMerge: true
{% endif %}
```

Why each part matters:
- `| default([])` and `| default(false)` keep both inputs optional: a
  flavor or a create without them renders as before.
- `| tojson` quotes each source and mirror, so a wildcard source such as
  `*.example.com` stays valid YAML (an unquoted `*` would start a YAML alias).
- The two `{% if %}` blocks write the keys only when given. Day1 checks
  every rendered file holds exactly the mirrors given, and refuses it if
  not.

A person with rights on the specs project merges it. Record the MR.

**Check it before and after the merge,** without creating anything:

1. Before the merge, render it as ArgoCD does for one existing cluster with
   the chart, as in [legacy-to-ecosystem.md](legacy-to-ecosystem.md) step 4.4
   (`helm template` with the four value layers and the rendered file). A
   file rendered without mirrors must be the same as before the change.
2. After the merge (and the upgrade, step 5), the template's inputs list
   both, with a session token as in 3.3-to-3.4's step 8:

   ```bash
   curl -s -H "Authorization: Bearer $SESSION" \
     "https://<route host>/api/day1/specs/template/schema" | grep -o '"name": *"[a-z_]*"'
   ```

   Expect `image_content_sources` and `disable_idms_merge` among them.
   Missing: the MR did not reach the default branch; **STOP**.
3. On the create form, choose any flavor and press **Preview** (it runs
   every check and commits nothing). Without mirrors, the file is as
   before. Add one mirror entry (an invented source such as
   `registry.example.com/test` and mirror `mirror.example.com/test`) and
   Preview again: the file shows `imageContentSources:` with that entry.
   Leave the form without creating.

## 5. Upgrade

```bash
helm upgrade <release> $CHART -n <ns> --reset-then-reuse-values \
  --set image.day1.tag=<tag> --set image.day2.tag=<tag> --set image.web.tag=<tag>
kubectl -n <ns> rollout status deploy -l app.kubernetes.io/part-of=wingman --timeout=5m
```

## 6. Verify

1. The Flavors page loads every flavor as before, and no flavor shows a new
   warning (no flavor has mirrors yet).
2. If step 4 was done: its checks 2 and 3 pass.
3. If step 4 was not done: open the flavor editor, give an unsaved test
   flavor one mirror entry and press Review, then Save. Expect a refusal
   that names `image_content_sources` and this guide. Do not save anything
   else; close the editor. If the save is accepted instead, it opened a
   merge request on the specs project: close it unmerged, and **STOP** (the
   template reads the inputs after all; step 3 missed it).

## 7. Roll back and report

Roll back the release with `helm rollback <release> <previous revision> -n <ns>`.
3.44 ignores the new inputs: a flavor that gives mirrors still passes them
to the template, a lock on them is shown as not enforced, and drift does not
compare them. Revert step 4's MR only when no flavor gives mirrors: a
template without the lines would create those flavors' clusters without
them. Report: the tag deployed, whether step 4 was done (its MR), step 3's
answers, and step 6's results.
